# Implementation Plan: Summary Scoring & Prompt Engineering

**Branch**: `feat/tae-82-summary-scoring-prompt-engineering` | **Date**: 2026-07-27 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/tae-82-summary-scoring-prompt/spec.md`

## Summary

Extend the existing `TranscriptSummarizer` class in `src/integrations/claude/` to support a structured, rubric-signal-driven summarization mode. Currently the class sends the raw transcript to the Claude API with no system prompt and returns a plain string. This feature adds:

1. A prompt builder (`src/integrations/claude/prompt.ts`) that constructs a system prompt embedding the rubric signal list and structured JSON output instructions.
2. A Zod schema (`src/schemas/ai-summary-response.schema.ts`) that validates the AI's camelCase JSON response.
3. Pure scoring utilities (`src/lib/utils/scoring.utils.ts`) for signal simplification and highest-tier-wins band classification.
4. An extension to `SummarizationOptions` accepting `signals?: SimplifiedSignal[]` and a new `StructuredSummarizationResult` type for the structured success path.
5. A branch in the summarizer: when signals are passed → structured prompt+validation+scoring path; when omitted → existing raw transcript path (backward compat).

**Scope**: Claude integration layer only. The server action, rubric signal fetching from MongoDB, and OpenRouter integration are handled by a teammate and are explicitly out of scope.

## Technical Context

**Scale/Scope**: Single-tenant, small sales team; typical transcripts 30–90 min calls

## Detailed Design

### 1. Type additions — `src/types/rubric-signal.types.ts`

Add `SimplifiedSignal` interface after the existing `RubricSignalFields`:

```typescript
export interface SimplifiedSignal {
  id: string;
  label: string;
  tier: SignalWeight;
  hints?: string[];
}
```

The `hints` field is optional and only included when the source signal has a non-empty `hints` array. Callers building `SimplifiedSignal[]` from `RubricSignalFields[]` can use the `simplifySignals` utility.

### 2. Type additions — `src/types/claude.types.ts`

Add `signals` to `SummarizationOptions` and add `StructuredSummarizationResult`:

```typescript
// New import needed at top of file
import type { SimplifiedSignal } from '@/types/rubric-signal.types';
import type { TranscriptLeadScore, TranscriptSummary } from '@/types/transcript.types';

// Extended options
export interface SummarizationOptions {
  model?: string;
  maxTokens?: number;
  signals?: SimplifiedSignal[];
}

// New structured success type (when signals are provided)
export interface StructuredSummarizationResult {
  success: true;
  summary: TranscriptSummary;
  leadScore: TranscriptLeadScore;
  model: string;
  usage: {
    inputTokens: number;
    outputTokens: number;
  };
}

// Updated union — SummarizationResult (raw) | StructuredSummarizationResult | SummarizationError
export type SummarizationResponse =
  | SummarizationResult
  | StructuredSummarizationResult
  | SummarizationError;
```

Callers differentiate result shapes via `'summary' in result` (structured) vs `'content' in result` (raw).

### 3. Prompt builder — `src/integrations/claude/prompt.ts`

Exports a single function `buildSummarizationPrompt(signals: SimplifiedSignal[]): { system: string }`.

The system prompt:
- States the AI's role as a sales call analyst
- Instructs JSON-only output (no markdown fences, no preamble)
- Embeds the full camelCase output schema as documentation
- Includes the simplified signal list as a JSON array
- Instructs the model to detect only signals from the provided list (no hallucination)
- Explains the `detectedSignals[].evidence` requirement

The user message is the transcript text directly (no wrapping needed — the system prompt contextualizes it).

When `signals` is an empty array, the system prompt still instructs structured output but the signal list is empty, and the model should return `leadScoreBand: "cold"` with an empty `detectedSignals` array.

### 4. Zod schema — `src/schemas/ai-summary-response.schema.ts`

```typescript
import { z } from 'zod';

export const AiSummaryResponseSchema = z.object({
  narrative: z.string().min(1),
  whatWeHeard: z.array(z.string()).default([]),
  whatWasCovered: z.array(z.string()).default([]),
  whatWasDecided: z.array(z.string()).default([]),
  actionItems: z.array(z.object({
    description: z.string().min(1),
    owner: z.string().min(1),
    dueDate: z.string().nullable().optional().default(null),
  })).default([]),
  attendees: z.array(z.object({
    name: z.string().min(1),
    side: z.enum(['kaffeax', 'prospect']),
  })).default([]),
  detectedSignals: z.array(z.object({
    id: z.string().min(1),
    label: z.string().min(1),
    evidence: z.string().min(1),
  })).default([]),
  leadScoreBand: z.enum(['hot', 'warm', 'cold']),
  scoreRationale: z.string().min(1),
});

export type AiSummaryResponse = z.infer<typeof AiSummaryResponseSchema>;
```

Hallucinated signal IDs are filtered in the summarizer after validation (strip `detectedSignals` entries whose `id` is not in the input signals list, log a warning per halluicnation).

### 5. Scoring utilities — `src/lib/utils/scoring.utils.ts`

Two exported functions:

**`simplifySignals(signals: RubricSignalFields[]): SimplifiedSignal[]`** — converts full rubric signal objects to the lightweight format expected by the prompt builder. Exported here for use by the teammate's server action layer.

**`determineBand(detectedSignals: DetectedSignal[], inputSignals: SimplifiedSignal[]): LeadScoreBand`** — highest-tier-wins logic: builds a tier map from input signals, iterates detected signal IDs, returns "hot" if any hot found, "warm" if any warm found (and no hot), "cold" otherwise. When `detectedSignals` is empty or none of the IDs match the input, returns "cold".

### 6. Summarizer update — `src/integrations/claude/transcript-summarizer.ts`

The `summarize(transcript, options?)` method branches on `options?.signals`:

**Unstructured path** (no signals, backward compatible — unchanged):
- Send transcript as user message with no system prompt
- Return `SummarizationResult { success: true, content: string, ... }`

**Structured path** (signals provided, including empty array):
- Call `buildSummarizationPrompt(options.signals)` to get `{ system }`
- Call `client.messages.stream({ ..., system, messages: [{ role: 'user', content: transcript }] })`
- Accumulate text blocks from response stream
- Strip any accidental markdown fences (defensive: `text.replace(/^```json\s*/i, '').replace(/```\s*$/, '')`)
- `JSON.parse(text)` in try-catch — if fails, return `SummarizationError { category: 'api_error', ... }`
- `AiSummaryResponseSchema.safeParse(parsed)` — if fails, return `SummarizationError { category: 'api_error', ... }`
- Filter `detectedSignals` to only IDs in input signals; log warning for any stripped entries
- Compute authoritative band via `determineBand(validatedSignals, options.signals)`
- Compare with AI's `leadScoreBand` — log warning if they disagree
- Construct `TranscriptSummary` and `TranscriptLeadScore` from validated response
- Return `StructuredSummarizationResult { success: true, summary, leadScore, model, usage }`

Error handling in the structured path uses the same `catch` block as the existing path — all SDK error types already handled.

